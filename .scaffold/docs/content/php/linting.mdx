# Linting

You check PHP code with 3 tools: PHP_CodeSniffer for coding standards, PHPStan for static analysis and Rector for automated refactoring. This page is for developers working in a project generated from Scaffold. It covers how to run the tools and what each configuration file sets.

## Usage

To check the code, run `composer lint`. It runs PHP_CodeSniffer, PHPStan and `rector --dry-run`, which report problems without changing files.

To fix what the tools can fix, run `composer lint-fix`. It runs Rector, then the PHP_CodeSniffer fixer, `phpcbf`. PHPStan has no fixer, so fix its errors by hand.

PHP_CodeSniffer and PHPStan check these paths, depending on the PHP mode you picked in `init.sh`:

| Path | PHP mode |
|------|----------|
| `src` | A CLI command app or a library |
| `bin/php-command` | A CLI command app |
| `php-script` | A CLI script |
| `tests/phpunit` | Every mode |

`init.sh` renames `bin/php-command` or `php-script` to the name you choose and updates the path in `phpcs.xml` and `phpstan.neon`. To check another directory, add it to both files.

The `Test PHP` workflow runs `composer lint` in 1 job of its matrix, the PHP 8.4 job with normal dependencies. See [Test](../ci/test).

## PHP_CodeSniffer

[PHP_CodeSniffer](https://github.com/squizlabs/PHP_CodeSniffer) analyzes PHP files and detects violations of a coding standard.

The [`phpcs.xml`](https://github.com/AlexSkrypnyk/scaffold/blob/main/phpcs.xml) file is a minimal ruleset to customize. It lists the following standards:

- The Drupal coding standards, from the [`drupal/coder`](https://www.drupal.org/project/coder) package
- The DrevOps standard, from the `drevops/phpcs-standard` package
- `Generic.PHP.RequireStrictTypes`, which requires `declare(strict_types=1);` in every file

Composer installs both packages as development dependencies. In test files, the ruleset allows long array lines and functions without a doc comment. The ruleset also turns on sniff codes, progress and colors in the output.

For every option a ruleset accepts, see [the Annotated Ruleset page](https://github.com/squizlabs/PHP_CodeSniffer/wiki/Annotated-Ruleset).

## PHPStan

[PHPStan](https://phpstan.org/), the PHP Static Analysis Tool, finds errors in your code without running it.

The [`phpstan.neon`](https://github.com/AlexSkrypnyk/scaffold/blob/main/phpstan.neon) file sets `level` to `9`, and the template's code and tests pass at that level. PHPStan's strictest level is `10`. Adjust the level in `phpstan.neon` to suit your project.

PHPStan ignores the `no value type specified in iterable type array` error in `tests/phpunit`, so test methods and data providers can skip parameter docblocks.

For the full configuration reference, see the [PHPStan website](https://phpstan.org/config-reference).

## Rector

[Rector](https://getrector.com/) upgrades and refactors PHP code automatically.

The [`rector.php`](https://github.com/AlexSkrypnyk/scaffold/blob/main/rector.php) file is a starting configuration to customize. It turns on the following sets and rules:

- The PHP 8.3 upgrade set
- The `deadCode`, `codeQuality`, `codingStyle`, `typeDeclarations`, `naming`, `instanceOf`, `earlyReturn` and `phpunitCodeQuality` prepared sets
- The PHPUnit sets for the PHPUnit version installed by Composer
- `DeclareStrictTypesRector`, which adds `declare(strict_types=1);` to each file

It also turns off 12 rules from those sets. Rector replaces fully qualified class names in code with `use` imports. It leaves docblocks and global classes, such as `\Exception`, as they are.

Rector processes every `.php` and `.inc` file in the project, skipping `vendor` and `node_modules`, so it picks up `.php` files in a new directory without a change.

For the full configuration reference, see the [Rector website](https://getrector.com/documentation/).
