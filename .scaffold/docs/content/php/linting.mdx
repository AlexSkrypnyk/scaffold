# Linting

Scaffold sets up 3 tools to check PHP code: PHP_CodeSniffer for coding standards, PHPStan for static analysis and Rector for automated refactoring. Use this page to run the tools in a Scaffold project and to look up what each configuration file sets.

## Commands

The following table lists the lint commands:

| Command | What it does |
|---------|--------------|
| `composer lint` | Runs PHP_CodeSniffer, PHPStan and `rector --dry-run`. All 3 report problems without changing files. |
| `composer lint-fix` | Fixes code with Rector, then with `phpcbf`, the PHP_CodeSniffer fixer. PHPStan has no fixer, so fix its errors by hand. |

The `Test PHP` workflow runs `composer lint` in its PHP 8.4 job with the latest dependency versions. See [Test](../ci/test.mdx).

## Checked paths

PHP_CodeSniffer and PHPStan check these paths, depending on the PHP mode:

| Path | PHP mode |
|------|----------|
| `src` | A CLI command app or a library |
| `bin/php-command` | A CLI command app |
| `php-script` | A CLI script |
| `tests/phpunit` | Every mode |

`init.sh` renames `bin/php-command` or `php-script` to the name you choose and updates its path in `phpcs.xml`, `phpstan.neon` and `rector.php`. To check another directory with PHP_CodeSniffer and PHPStan, add it to `phpcs.xml` and `phpstan.neon`.

Rector checks every `.php` and `.inc` file outside `vendor` and `node_modules`, so a new directory needs no change to `rector.php`. It also checks the extensionless entry point, which `rector.php` lists by name. To check another file with no extension, add its path to `withPaths()` in `rector.php`.

## PHP_CodeSniffer

[PHP_CodeSniffer](https://github.com/squizlabs/PHP_CodeSniffer) checks PHP files against a coding standard.

The [`phpcs.xml`](https://github.com/AlexSkrypnyk/scaffold/blob/main/phpcs.xml) file is a minimal ruleset to customize. It lists the following standards and sniffs:

- The Drupal coding standards, from the [`drupal/coder`](https://www.drupal.org/project/coder) package
- The DrevOps standard, from the `drevops/phpcs-standard` package
- `Generic.PHP.RequireStrictTypes`, which requires `declare(strict_types=1);` in every file

Both packages are development dependencies. In test files, which end in `Test.php`, `TestCase.php` or `.test`, PHP_CodeSniffer allows long array lines and functions without a docblock. The ruleset's `arg` entries add sniff codes, progress and colors to the output.

For every ruleset option, see [Annotated ruleset](https://github.com/squizlabs/PHP_CodeSniffer/wiki/Annotated-Ruleset).

## PHPStan

[PHPStan](https://phpstan.org/) finds errors in your code without running it.

The [`phpstan.neon`](https://github.com/AlexSkrypnyk/scaffold/blob/main/phpstan.neon) file sets `level` to `9`. The template's code and tests pass at that level. To make the checks stricter or looser, change `level`. Level `10` is the strictest.

PHPStan ignores the `no value type specified in iterable type array` error in `tests/phpunit`, so test methods and data providers can take `array` parameters without a docblock that types their values.

For every setting, see the [PHPStan config reference](https://phpstan.org/config-reference).

## Rector

[Rector](https://getrector.com/) upgrades and refactors PHP code automatically.

The [`rector.php`](https://github.com/AlexSkrypnyk/scaffold/blob/main/rector.php) file is a starting configuration to customize. It lists the following sets and rules:

- The PHP 8.3 upgrade set
- The `deadCode`, `codeQuality`, `codingStyle`, `typeDeclarations`, `naming`, `instanceOf`, `earlyReturn` and `phpunitCodeQuality` prepared sets
- The PHPUnit sets for the PHPUnit version that Composer installs
- `DeclareStrictTypesRector`, which adds `declare(strict_types=1);` to each file

It also lists 12 rules from those sets to skip. Rector replaces fully qualified class names in code with `use` imports. It leaves global classes such as `\Exception` and the names in docblocks as written.

For every setting, see the [Rector documentation](https://getrector.com/documentation/).
