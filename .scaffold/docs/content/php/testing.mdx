# Testing

The template ships a [PHPUnit](https://phpunit.de/) 11 configuration and keeps the example tests for the PHP mode you pick: [CLI command](./php-command.mdx), [CLI script](./php-script.mdx) or [library](./php-library.mdx). This page is for developers running and writing tests in a project made from Scaffold. It covers the test layout, the PHPUnit settings and the coverage reports.

## PHPUnit

The tests live in `tests/phpunit/`, in 2 directories:

- `Unit/` for tests that call your code directly
- `Functional/` for tests that run a whole command or script

With the settings in [phpunit.xml](https://github.com/AlexSkrypnyk/scaffold/blob/main/phpunit.xml), PHPUnit does the following:

- Runs the tests that failed last time first, while keeping each test after the tests it depends on.
- Marks a test as risky when it prints output.
- Fails the run on risky tests and on warnings.
- Shows details for tests that trigger warnings, errors, notices or deprecations.
- Reports notices and warnings only from your source: `src`, or the script file in CLI script mode.
- Ignores indirect deprecations.

To run all the tests without coverage, run the following command:

```bash
composer test
```

To run only the tests in 1 group, tag a test class or method with a group attribute such as `#[Group('wip')]`, then run the following command:

```bash
composer test -- --group=wip
```

## Namespaces

Composer loads the tests through the `autoload-dev` section of `composer.json`, which maps the `YourNamespace\App\Tests\` namespace to `tests/phpunit`. `init.sh` replaces `YourNamespace` with the namespace you give it, in the tests and in `composer.json`.

## Coverage

`composer test-coverage` runs the tests and measures coverage of `src`. In CLI script mode, it measures the script file. PHPUnit needs a coverage driver such as PCOV or Xdebug. The following commands set `XDEBUG_MODE=coverage`, which Xdebug needs and PCOV ignores.

To run the tests with coverage, run the following command:

```bash
XDEBUG_MODE=coverage composer test-coverage
```

To get coverage for the tests in 1 group, run the following command:

```bash
XDEBUG_MODE=coverage composer test-coverage -- --group=wip
```

PHPUnit writes the coverage reports to `.logs/` in the project root. Git ignores `.logs`. The following table lists the reports:

| Format | File | Use |
|---|---|---|
| HTML | `.logs/.coverage-html/index.html` | Browse coverage file by file. |
| Cobertura | `.logs/cobertura.xml` | Feed coverage to other tools. |
| Text | `.logs/coverage.txt` | Read the coverage summary. |

With both `composer test` and `composer test-coverage`, PHPUnit writes test results to `.logs/junit.xml` in JUnit format.

With the coverage settings in `phpunit.xml`, PHPUnit does the following:

- Requires coverage metadata, such as `#[CoversClass]`, on every test.
- Accepts a test that runs more code than its metadata lists.
- Includes uncovered files in the report.
- Leaves path coverage off.
- Ignores deprecated code units.
- Honors `@codeCoverageIgnore` annotations.

The `Test PHP` GitHub Actions workflow runs `composer test-coverage`. It checks the Cobertura report against a coverage threshold and posts the text report to the pull request as a comment. See [Code coverage](../ci/test#code-coverage).
