# CLI command

In CLI command mode, your project is a console app built on the [Symfony Console component](https://symfony.com/doc/current/components/console.html). Use it for a tool with several commands or shared logic. This page is for developers building that tool from Scaffold. Follow it to add a command, test it and ship the app. For a tool that does 1 task with no dependencies, see [CLI script](./php-script.mdx).

`install.sh` selects this mode by default. It replaces `php-command` with your project name, or with the value of `--php-command-name`, in filenames and file contents. This page uses the placeholder name, `php-command`.

## App structure

The app has 2 parts:

- **The launcher**, [`bin/php-command`](https://github.com/AlexSkrypnyk/scaffold/blob/main/bin/php-command). It loads the Composer autoloader, creates a Symfony Console `Application`, registers each command and runs the app.
- **The command classes**, in [`src/Command/`](https://github.com/AlexSkrypnyk/scaffold/tree/main/src/Command). Each class extends `Symfony\Component\Console\Command\Command` and holds the logic of 1 command.

Symfony Console parses arguments and options, prints help and styles the output.

## Example commands

The following table lists the 2 example commands:

| Class | Command name | What it does |
|---|---|---|
| `SayHelloCommand` | `say-hello` | Prints a greeting and returns `Command::SUCCESS`. Sets a description and a help text. |
| `RollDiceCommand` | `roll-dice` | Rolls dice and prints each roll and the total. The `--sides` option sets the sides on each die: at least 2, with `6` as the default. The `--count` option sets the number of dice: 1 to 100, with `1` as the default. If an option is out of range or isn't a whole number, prints an error and returns `Command::FAILURE`. |

The launcher makes `RollDiceCommand` the default with `setDefaultCommand()`, so `./bin/php-command` with no command name runs `roll-dice`.

After `composer install`, run the `say-hello` command from the project root:

```bash
./bin/php-command say-hello
```

The command prints `Hello, Symfony console!`.

## Add a command

Each command is a class in `src/Command/` that you register in `bin/php-command`. To add a command of your own:

1. In `src/Command/`, copy an example class to a new file named after your class:
   - For a command with no input, copy `SayHelloCommand.php`.
   - For a command with options, copy `RollDiceCommand.php`.
2. In the new file, rename the class to match the new filename.
3. In `configure()`, set the name, description and help text of the command and add its arguments and options.
4. In `execute()`, replace the example code with your logic. Return `Command::SUCCESS` or `Command::FAILURE`.
5. In `bin/php-command`, add a `use` line and an `$application->add()` call for your class, the same way the launcher registers `SayHelloCommand`.
6. Add a test for the command in `tests/phpunit/Functional/`, with the `#[Group('command')]` attribute. See [Test a command](#test-a-command).
7. Run the command:

   ```bash
   ./bin/php-command COMMAND_NAME
   ```

   Replace `COMMAND_NAME` with the name you set in `configure()`. Confirm that the output matches what `execute()` writes.

## Test a command

The command tests live in [`tests/phpunit/Functional/`](https://github.com/AlexSkrypnyk/scaffold/tree/main/tests/phpunit/Functional). They use `ApplicationTrait` from [`alexskrypnyk/phpunit-helpers`](https://github.com/AlexSkrypnyk/phpunit-helpers), which wraps Symfony's `ApplicationTester`. The tests call 2 methods of `ApplicationTrait`:

- `applicationInitFromCommand()` builds an app around 1 command.
- `applicationRun()` runs the app and returns its output.

[`SayHelloCommandTest.php`](https://github.com/AlexSkrypnyk/scaffold/blob/main/tests/phpunit/Functional/SayHelloCommandTest.php) checks the greeting. [`RollDiceCommandTest.php`](https://github.com/AlexSkrypnyk/scaffold/blob/main/tests/phpunit/Functional/RollDiceCommandTest.php) mocks `rollDie()` to return fixed rolls, so it can check the exact output.

Both tests carry the `#[Group('command')]` attribute. To run only that group, run the following command:

```bash
composer test -- --group=command
```

For the PHPUnit configuration and coverage reports, see [Testing](./testing.mdx).

## Ship the app

Ship the app as a PHAR, as a Composer package or both. Box compiles `bin/php-command` into the PHAR, and Composer links the same file into `vendor/bin`:

- **As a PHAR:** A PHAR is 1 executable file that holds the app and its dependencies, so users need only PHP. `composer build` compiles it into `dist/php-command.phar`. When you push a tag, the `Release PHP` workflow builds the PHAR and attaches it to the GitHub release for the tag. `install.sh` sets up the PHAR build and release unless you pass `--no-phar`. For the build steps, the PHAR version and what `--no-phar` removes, see [PHP packaging](../ci/php-packaging.mdx).
- **As a Composer package:** Publish the project to Packagist.org, the Composer package registry. In a project that requires your package, developers run `vendor/bin/php-command`. The launcher looks for that project's autoloader first and falls back to its own, so it runs both as a dependency and from its own checkout. Git ignores `dist`, so the package holds no PHAR.
