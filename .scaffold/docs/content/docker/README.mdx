# Docker

Docker support adds a `Dockerfile` and an entrypoint script to your project, with GitHub Actions workflows that lint the `Dockerfile`, then test and publish the image. The pages in this section are for developers who build or publish that image in a project generated from Scaffold.

Docker support is off by default. To turn it on, run `install.sh` with `--docker` or answer `y` to its **Use Docker** prompt. The image name defaults to your namespace in lowercase and your project name, such as `acmeapp/acme-app`. To pick another name, pass `--docker-image-name` or answer the **Docker image name** prompt. `--docker-image-name` also turns Docker support on.

Pick the page for your task:

- [Image](./image.mdx): see what `Dockerfile` and `entrypoint.sh` contain, then build and run the image
- [Linting](./linting.mdx): check the `Dockerfile` with Hadolint
- [Testing](./testing.mdx): see what `.github/workflows/test-docker.yml` checks
- [Publishing](./publishing.mdx): publish the image to Docker Hub
