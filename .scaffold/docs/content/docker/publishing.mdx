# Publishing

2 GitHub Actions workflows build your project's image for `linux/amd64` and `linux/arm64` and push it to Docker Hub. This page is for developers who publish that image from a project generated from Scaffold. It covers when each tag gets published and how to set up the credentials and the image name the workflows use.

## Published tags

The following table lists the image tags each workflow pushes:

| Tag | Workflow | When |
|---|---|---|
| `canary` | [`test-docker.yml`](./testing.mdx) | On a push to `main`, after the workflow's tests pass |
| The Git tag's name and `latest` | [`release-docker.yml`](https://github.com/AlexSkrypnyk/scaffold/blob/main/.github/workflows/release-docker.yml) | On a push of a Git tag whose name has no `/` |

The `canary` tag points to the last image that the `Docker canary` job pushed from `main`, so you can try changes between tagged releases. The workflows never publish an image from a pull request, including one from a fork. To change the image tags for a release, edit the `docker/metadata-action` step in `release-docker.yml`.

## Set up Docker Hub credentials

Both workflows sign in to Docker Hub with 2 repository secrets. To add them:

1. In your repository, open **Settings > Secrets and variables > Actions**.
2. On the **Secrets** tab, add a `DOCKER_USER` secret with your Docker Hub username.
3. Add a `DOCKER_PASS` secret with a Docker Hub access token.
4. Push a commit to `main`. Confirm that the **Docker canary** job of `test-docker.yml` passes on the **Actions** tab.

## Override the image name

Both workflows publish to the image name from `install.sh`. To publish to another image without editing the workflows, set the `DOCKER_IMAGE` repository or organization variable to that image name. Create it on the **Variables** tab of the same settings page, because the workflows ignore a secret with that name. For example, point `DOCKER_IMAGE` at a throwaway Docker Hub repository to test the pipeline end to end.
