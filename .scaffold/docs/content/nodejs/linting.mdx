# Linting

[ESLint](https://eslint.org/) reports problem patterns and coding-standard violations in NodeJS code. [Prettier](https://prettier.io/), an opinionated code formatter, reprints the code in its own style. This page is for developers who change `nodejs-script` or its tests in a project generated from Scaffold. Follow it to run both tools, fix what they report and change their settings.

## Check the code

Both tools check `nodejs-script`, `eslint.config.js` and the `.js` files in `tests/nodejs` and its subdirectories. To check these files:

1. In your project root, install ESLint and Prettier with the project's other development dependencies:

   ```bash
   npm install
   ```

2. Run the following command:

   ```bash
   npm run lint
   ```

   ESLint lists each problem it finds. Prettier runs only when ESLint finds no problems, and lists the files that need formatting.

The `Test Node.js` workflow runs `npm run lint` in CI, in its Node.js 22 job only. See [Test](../ci/test.mdx).

## Fix the code

To fix what the tools can fix automatically, run `npm run lint-fix`. It runs ESLint with `--fix`. When no ESLint problems remain after those fixes, it runs Prettier with `--write`, which reformats the files in place.

## Lint another file

To add a file to both tools:

1. In `package.json`, add the file's path to the ESLint command and the Prettier command of both the `lint` and `lint-fix` scripts.
2. In `eslint.config.js`, add the path to the `files` array, which lists the files the ESLint rules apply to.
3. For a file with no `.js` extension, add an entry for it to `prettier.overrides` in `package.json` with the `babel` parser, as the entry for `nodejs-script` does.

## ESLint settings

The [`eslint.config.js`](https://github.com/AlexSkrypnyk/scaffold/blob/main/eslint.config.js) file is a starting ruleset to customize. It sets the following:

- The ESLint recommended rules, for the paths in the `files` array
- ECMAScript 2022 syntax in CommonJS modules, with the Node.js globals defined
- `eslint-config-prettier`, which turns off the ESLint rules that conflict with Prettier

## Prettier settings

Prettier reads its settings from the `prettier` key in [`package.json`](https://github.com/AlexSkrypnyk/scaffold/blob/main/package.json). The template sets the following:

- `singleQuote` is `true`, so Prettier prefers single quotes for strings.
- An override sets the `babel` parser for `nodejs-script`, which has no `.js` extension for Prettier to pick a parser from.
