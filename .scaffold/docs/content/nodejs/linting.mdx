# Linting

You check NodeJS code with 2 tools. [ESLint](https://eslint.org/) reports problem patterns and coding-standard violations. [Prettier](https://prettier.io/), an opinionated code formatter, reprints the code in its own style. This page shows how to run both and where each one is configured.

## Usage

Both tools check `nodejs-script`, `eslint.config.js` and the `.js` files in `tests/nodejs` and its subdirectories.

To check the code, run `npm run lint`. It runs ESLint, then runs Prettier to report files that need formatting.

To fix what the tools can fix automatically, run `npm run lint-fix`. It runs ESLint with `--fix`, then Prettier with `--write` to reformat the files.

To lint another file:

1. Add its path to the ESLint and Prettier commands in the `lint` and `lint-fix` scripts in `package.json`.
2. Add the path to the `files` array in `eslint.config.js`.

In CI, the `Test Node.js` workflow runs `npm run lint` in its Node.js 22 job only. See [Test](../ci/test).

## ESLint

The [`eslint.config.js`](https://github.com/AlexSkrypnyk/scaffold/blob/main/eslint.config.js) file is a starting ruleset to customize. It sets the following:

- The ESLint recommended rules, for the paths in the `files` array
- ECMAScript 2022 syntax in CommonJS modules, with the Node.js globals defined
- `eslint-config-prettier`, which turns off the ESLint rules that conflict with Prettier

## Prettier

Prettier reads its settings from the `prettier` key in [`package.json`](https://github.com/AlexSkrypnyk/scaffold/blob/main/package.json). The template sets the following:

- `singleQuote` is `true`, so Prettier prefers single quotes for strings.
- An override makes Prettier parse `nodejs-script`, which has no `.js` extension, with the `babel` parser.
