# Testing

You test the `nodejs-script` file with the test runner built into Node.js and measure coverage with c8. This page shows how to run the tests, where new test files go and where c8 writes the coverage reports.

## Node.js test runner

[`node --test`](https://nodejs.org/api/test.html) is the test runner built into Node.js, so it needs no extra package. Tests assert with the `node:assert` module, and the runner isolates each test file in its own process.

To run all the tests, run the following command:

```bash
npm run test
```

When every test passes, the runner prints `# fail 0` in its summary and exits with code `0`.

`npm run test` passes `tests/nodejs/*.test.js` to the runner, so it runs only the test files at the top level of [`tests/nodejs`](https://github.com/AlexSkrypnyk/scaffold/tree/main/tests/nodejs). Put new test files there.

## Coverage

[`c8`](https://github.com/bcoe/c8) collects the coverage data that V8, the JavaScript engine in Node.js, records natively. c8 renders the data in several formats.

To run the tests and generate the coverage reports, run the following command:

```bash
npm run test-coverage
```

With the settings in [`.c8rc.json`](https://github.com/AlexSkrypnyk/scaffold/blob/main/.c8rc.json), c8 measures coverage of `nodejs-script` and writes these reports:

| Format | Output |
|--------|--------|
| Text | A summary table in the terminal |
| LCOV | `.logs/lcov.info` and an HTML report in `.logs/lcov-report` |
| Cobertura | `.logs/cobertura-coverage.xml` |

The Cobertura report is machine-readable, for other tools to consume. In the [Test](../ci/test) workflow, a step reads the Cobertura report and fails the run when line coverage is less than 80%. Another step uploads the report to Codecov. To change the threshold, set the `CI_CODE_COVERAGE_THRESHOLD` repository variable.
