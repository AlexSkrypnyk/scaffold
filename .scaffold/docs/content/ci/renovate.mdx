# Renovate

Scaffold configures [Renovate](https://renovatebot.com) to keep a project's dependencies up to date. Renovate scans the project files for dependencies, checks for newer versions and opens pull requests with the changes. This page is for maintainers who want to know which updates Renovate merges on its own, which ones stay manual and how to run Renovate on demand.

After you install the [Renovate GitHub app](https://github.com/apps/renovate) on your repository, Renovate reads its configuration from [`renovate.json`](https://github.com/AlexSkrypnyk/scaffold/blob/main/renovate.json).

## Configuration overview

The following table lists the top-level settings in `renovate.json`:

| Setting | Value | Description |
|---|---|---|
| `extends` | `config:recommended` | Inherits Renovate's recommended base configuration |
| `automerge` | `true` | If true, Renovate merges a pull request after all its checks pass |
| `rangeStrategy` | `bump` | Renovate raises the constraint to the new version, such as `^2.3.1` to `^2.3.2` |
| `dependencyDashboard` | `true` | If true, Renovate opens a GitHub issue that tracks every pending update |
| `pinDigests` | `true` | If true, Renovate pins Docker images and GitHub Actions to exact digests, so builds are reproducible |
| `branchPrefix` | `deps/` | Renovate starts every branch name with this prefix |

## Update rules

A catch-all rule in `packageRules` sets every package's group to `all dependencies`. Renovate batches the pending updates in that group into 1 pull request on the `deps/all` branch. Major updates go into a second pull request, on `deps/major-all`.

### Language version constraints

Renovate skips the language version constraints, so you update them by hand:

| Constraint | Manager | Why |
|---|---|---|
| `php` | Composer | A PHP version change affects the entire runtime environment |
| `node`, `yarn` | npm | A Node.js or Yarn version change affects the build toolchain |

### Major version updates

Renovate skips major updates for npm and Composer packages, because a major version can contain breaking changes. The following table lists the updates each manager receives:

| Manager | Major updates | Minor/patch updates |
|---|---|---|
| **npm** | Disabled | Enabled (automerge) |
| **Composer** | Disabled | Enabled (automerge) |
| **GitHub Actions** | Enabled (automerge) | Enabled (automerge) |
| **Docker** | Enabled (automerge) | Enabled (automerge) |

To move an npm or Composer package to a new major version, edit its constraint by hand, then run `composer update` or `npm install`.

### Class library `require` constraints

A class library's `require` block sets the oldest versions its consumers can install. The library doesn't commit `composer.lock`, so a `bump` of `require` changes nothing the library itself installs. It only raises the minimum for every consumer.

When `init.sh` generates a class library, it adds this rule to `renovate.json`:

```json
{
    "matchManagers": ["composer"],
    "matchFileNames": ["composer.json"],
    "matchDepTypes": ["require"],
    "enabled": false
}
```

Renovate keeps updating `require-dev`, which consumers never install. The `matchFileNames` value limits the rule to the root `composer.json`, so a nested `composer.json`, such as a test fixture, still gets `require` updates.

## Template initialization

`init.sh` adjusts `renovate.json` to the features you select:

| Features selected | Changes to configuration |
|---|---|
| PHP + NodeJS | None: every rule stays |
| PHP only | Removes the `node`/`yarn` language rule and `"npm"` from the rule that blocks major updates |
| NodeJS only | Removes the `php` language rule and `"composer"` from the rule that blocks major updates |
| Neither PHP nor NodeJS | Removes the language rules and the rule that blocks major updates |
| PHP class library | Adds the rule that disables `require` updates in the root `composer.json` |

When you answer no to "Use Renovate" or pass `--no-renovate`, `init.sh` deletes `renovate.json` and the `update-dependencies.yml` workflow.

## Run Renovate on demand

The Renovate GitHub app updates dependencies on its own schedule. To get updates between its runs, start the **Update dependencies** workflow, [`update-dependencies.yml`](https://github.com/AlexSkrypnyk/scaffold/blob/main/.github/workflows/update-dependencies.yml), by hand. The workflow runs Renovate a single time with your `renovate.json` and lifts the schedule and pull request limits for that run.

The workflow pushes branches and opens pull requests with a token from the `RENOVATE_TOKEN` repository secret, and fails at its first step without it. Use a personal access token with the permissions in Renovate's [GitHub platform guide](https://docs.renovatebot.com/modules/platform/github/). The built-in `GITHUB_TOKEN` can't update workflow files, and its pull requests start no CI runs.

To run Renovate on demand:

1. If your repository has no `RENOVATE_TOKEN` secret, add it under **Settings > Secrets and variables > Actions**.
2. In your repository on GitHub, click **Actions**.
3. Select the **Update dependencies** workflow.
4. Click **Run workflow** to open the run options.
5. Optional: To list the updates in the job log without pushing anything, select **Dry run: report updates without pushing branches or opening pull requests.**
6. Optional: To troubleshoot a run, select **Enable debug logging.**
7. Click the green **Run workflow** button. After the run finishes, confirm that the **Pull requests** tab lists the dependency pull requests. On a dry run, the job log lists the updates.

The workflow commits as `renovate[bot]`, the Renovate app's account, so the app and the workflow update the same branches and pull requests. To commit as another author, set the `RENOVATE_GIT_AUTHOR` repository variable to `Name <email@example.com>`. The workflow leaves the Dependency Dashboard to the app.

## Dependency dashboard

The [Dependency Dashboard](https://docs.renovatebot.com/key-concepts/dashboard/) is a GitHub issue that lists the following:

- Available updates scheduled for later
- Updates that the configuration rules filter out
- Failed update attempts and their reasons
