# Renovate

[Renovate](https://renovatebot.com) is a bot that finds your project's dependencies, checks for newer versions and opens pull requests that update them. This page is for maintainers of a project created from Scaffold. It lists what Scaffold's `renovate.json` sets, which updates Renovate merges on its own and which ones you make by hand.

After you install the [Renovate GitHub app](https://github.com/apps/renovate) on your repository, the app reads [`renovate.json`](https://github.com/AlexSkrypnyk/scaffold/blob/main/renovate.json) and runs on its own schedule. To start a run between the app's runs, see [Run Renovate on demand](renovate-on-demand.mdx).

## Settings

The following table lists the top-level settings in `renovate.json`:

| Setting | Value | Effect |
|---|---|---|
| `extends` | `config:recommended` | Inherits Renovate's recommended base configuration. |
| `automerge` | `true` | If true, Renovate merges a pull request after all its checks pass. |
| `rangeStrategy` | `bump` | Renovate raises the version constraint to the new version, such as `^2.3.1` to `^2.3.2`. |
| `dependencyDashboard` | `true` | If true, Renovate opens the [Dependency Dashboard](https://docs.renovatebot.com/key-concepts/dashboard/), a GitHub issue that lists pending updates, updates scheduled for later and failed updates. |
| `pinDigests` | `true` | If true, Renovate pins Docker images and GitHub Actions to exact digests, so their versions are reproducible. |
| `branchPrefix` | `deps/` | Renovate starts every branch name with `deps/`. |

## Update rules

Renovate applies the rules in `packageRules`. A catch-all rule puts every package in the `all dependencies` group, with the slug `all`, so Renovate batches the updates into 1 pull request on the `deps/all` branch. Major updates for GitHub Actions and Docker go into a second pull request, on `deps/major-all`.

The following table lists the updates each package manager gets:

| Manager | Major updates | Minor and patch updates |
|---|---|---|
| npm | No pull request | Merged automatically |
| Composer | No pull request | Merged automatically |
| GitHub Actions | Merged automatically | Merged automatically |
| Docker | Merged automatically | Merged automatically |

A major version can contain breaking changes, so Renovate leaves npm and Composer majors to you. To move a package to a new major version, edit its constraint, then run `composer update` or `npm install`.

Renovate also skips the language version constraints, because each one changes the environment your code runs in. Update these constraints by hand:

| Constraint | File | What it changes |
|---|---|---|
| `php` | `composer.json` | The PHP runtime |
| `node`, `yarn` | `package.json` | The Node.js build toolchain |

## Class library rule

A class library's `require` block sets the oldest versions its consumers can install. The library commits no `composer.lock`, so bumping `require` changes nothing the library installs and only raises the minimum for every consumer.

For a class library, `install.sh` adds this rule to `renovate.json`:

```json
{
    "matchManagers": ["composer"],
    "matchFileNames": ["composer.json"],
    "matchDepTypes": ["require"],
    "enabled": false
}
```

The rule matches only the root `composer.json`, so a nested `composer.json`, such as a test fixture, still gets `require` updates. Renovate keeps updating `require-dev`, which consumers never install.

## Changes `install.sh` makes

`install.sh` adjusts `renovate.json` to the stacks you select:

| Stacks selected | Changes to `renovate.json` |
|---|---|
| PHP and Node.js | None |
| PHP only | Removes the `node`/`yarn` rule and `"npm"` from the rule that blocks major updates |
| Node.js only | Removes the `php` rule and `"composer"` from the rule that blocks major updates |
| Neither PHP nor Node.js | Removes the language rules and the rule that blocks major updates |
| PHP class library | Adds the [class library rule](#class-library-rule) |

To leave Renovate out of a new project, answer no to the `install.sh` prompt **Use Renovate** or pass `--no-renovate`. `install.sh` then deletes `renovate.json` and the `update-dependencies.yml` workflow.

For every Renovate option, see the [Renovate documentation](https://docs.renovatebot.com/).
