# PHP packaging

This page is for maintainers of a Scaffold console app who ship it as a PHP Archive (PHAR). It covers how to build, version and release the PHAR and which settings control its contents.

A PHAR bundles a PHP app and its dependencies into 1 executable file, the way a JAR file bundles a Java app. Users download that file and run it, and they need PHP installed, as a JAR needs Java. The format suits command-line tools, cron jobs and daemons that run outside a web server.

For a CLI command app, `init.sh` keeps this setup by default. Answering no to its **Build PHAR** prompt, or passing `--no-phar`, removes the PHAR setup:

- `box.json`
- The `build` script, the `bamarni/composer-bin-plugin` entries and `vendor-bin` in the `reset` script, all in `composer.json`
- The `/dist` and `/vendor-bin` entries in `.gitignore`
- The `Build PHAR` job of the `Test PHP` workflow
- The `Release PHP` workflow

## Workflow

The `build` script in `composer.json` runs [Box](https://github.com/box-project/box), a PHAR build tool that reads its settings from `box.json`. `composer build` runs 3 commands in order:

1. `@composer bin box require --dev humbug/box` installs Box into `vendor-bin/box` through the `bamarni/composer-bin-plugin` Composer plugin.
2. `box validate` checks `box.json`.
3. `box compile` writes the PHAR to `dist/php-command.phar`.

On every `Test PHP` run, the `Build PHAR` job builds the PHAR, then runs it with `--version` and with no arguments. A PHAR that fails to build or run fails the workflow.

The `Release PHP` workflow publishes the PHAR. It runs when you push a tag whose name has no `/`, or when you start it by hand from the **Actions** tab with a version. It builds and runs the PHAR with the same checks as the `Build PHAR` job. Then the `softprops/action-gh-release` action attaches the PHAR to the GitHub release for that version, and creates the release if it doesn't exist.

For an example, the [Releases](https://github.com/AlexSkrypnyk/scaffold/releases) page of the Scaffold repository shows a released PHAR under **Assets**.

## PHAR version

The PHAR prints its version with the `--version` flag. Box writes the version into the copy of `bin/php-command` inside the PHAR:

1. `bin/php-command`, the launcher, passes the `@yourproject-version@` placeholder to the Symfony Console `Application` class as its version.
2. Box replaces `@yourproject-version@` with the value of the `yourproject-version` key under `replacements` in `box.json`, which is `development`.
3. Before it builds, `Release PHP` replaces `development` with the release version in its own checkout of `box.json`. The change never reaches your repository.

The version depends on how the build starts:

| Build | Version |
|---|---|
| `Release PHP` on a tag push | The tag name as is, such as `1.2.3` |
| `Release PHP` started by hand | The required **Release version** input |
| `composer build` on your machine | `development` |

To print the version of your build, run the following command in the `dist` directory:

```bash
./php-command.phar --version
```

## Box

`box.json` sets which files go into the PHAR, where Box writes it and how Box compresses it. Scaffold ships this [`box.json`](https://github.com/AlexSkrypnyk/scaffold/blob/main/box.json):

import CodeBlock from '@theme/CodeBlock';
import MyComponentSource from '!!raw-loader!../../../../box.json';

<CodeBlock language="jsx">{MyComponentSource}</CodeBlock>

The following table describes each setting:

| Setting | Value | Effect |
|---|---|---|
| `main` | Unset | Box uses the first `bin` entry in `composer.json`, `bin/php-command`. The same launcher serves Composer installs and the PHAR. |
| `output` | `dist/php-command.phar` | Sets where Box writes the PHAR. Git ignores `dist`, so Git doesn't track the PHAR. |
| `compression` | `GZ` | Box compresses the PHAR with gzip, which makes the file smaller. |
| `finder` | Every file in `./`, excluding `dist`, `docs`, `php-script` and `tests` | Selects the files to bundle. Excluding `dist` keeps a previous build out of the next PHAR. |
| `blacklist` | 11 paths, such as `.github`, `phpcs.xml` and `box.json` | Box leaves these paths out of the PHAR. |
| `replacements` | `yourproject-version` set to `development` | Box puts this value in place of the version placeholder in the launcher. See [PHAR version](#phar-version). |

To change what the PHAR contains, edit these settings in `box.json`. The [Box documentation](https://box-project.github.io/box/) lists every setting.
