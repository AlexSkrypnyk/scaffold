# SSH into a GitHub Actions runner

Follow this page to open a shell on the runner of a test job, so you can debug a failure on the machine where it happened. It's for maintainers with write access to the repository and an SSH client.

The `Test PHP`, `Test Node.js`, `Test shell` and `Test Docker` workflows end each test job with a **Setup tmate session** step. The step uses the [mxschmitt/action-tmate](https://github.com/mxschmitt/action-tmate) action, which shares the runner's terminal over SSH through a tmate server. GitHub runs the step only on a run you start by hand with the **Enable terminal session.** checkbox selected. It runs last, even when an earlier step fails.

The workflows use the action's default server, the public tmate server. The [action-tmate README](https://github.com/mxschmitt/action-tmate#readme) states that the public tmate servers shut down in July 2025. Before you start, set the **Setup tmate session** step of the workflow you debug to use a tmate server you host, as that README explains.

To open an SSH session on a runner:

1. In your repository on GitHub, click **Actions**.
2. Select the workflow to debug, such as **Test PHP**.
3. Click **Run workflow** to open the run options.
4. Select the **Enable terminal session.** checkbox.
5. In the run options, click the green **Run workflow** button.
6. Click the new run.
7. Click the job to debug. The **Setup tmate session** step prints SSH details like these in the job log:

   ```text
   SSH: ssh qdpBWKjyXTsEsaSQxR8EscUuH@nyc1.tmate.io
   or: ssh -i <path-to-private-SSH-key> qdpBWKjyXTsEsaSQxR8EscUuH@nyc1.tmate.io
   ```

8. In your terminal, run the first `ssh` command from the log. If your SSH client needs a specific private key, run the second command with the path to that key.

The session stays open until you exit the shell, or until 30 minutes after GitHub starts the step.
