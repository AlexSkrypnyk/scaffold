# AI integration

Scaffold ships configuration that lets AI coding agents work in a generated project from the first commit. This page is for developers who use those agents. It covers each file, the commands an agent runs without asking and how to keep the architecture documentation current.

`init.sh` asks **Use AI agents** and keeps all of this configuration unless you answer no. Non-interactively, pass `--ai` or `--no-ai` to `init.sh`. With `--no-ai`, `init.sh` removes `CLAUDE.md`, `AGENTS.md` and the `.claude/` directory from the generated project.

## `AGENTS.md`

`AGENTS.md` holds the project's architecture, its lint, test and build commands and the coding conventions for an AI coding agent to follow. It follows the [AGENTS.md](https://agents.md/) convention, which many AI coding tools read.

`init.sh` trims the template's [`AGENTS.md`](https://github.com/AlexSkrypnyk/scaffold/blob/main/AGENTS.md) to the features you select. The generated file's "Updating from the template" section has the steps an agent follows to fetch the `update-consumer-scaffold` skill into the git-ignored `.claude/skills/update-consumer-scaffold/` directory.

## `CLAUDE.md`

[Claude Code](https://www.claude.com/product/claude-code) reads `CLAUDE.md` as its entry point. The file only imports `AGENTS.md`, so Claude Code reads the same guidance as other agents.

## `.claude/settings.json`

`.claude/settings.json` lists the project commands Claude Code runs without asking for confirmation, such as lint, test and build. The file is committed, so the whole team shares 1 list.

The list matches the commands documented in `AGENTS.md`. `init.sh` removes the entries for the features you didn't select, so a project without Docker pre-approves no Docker command.

A command that runs a repository-defined script, installs packages or starts a container is pre-approved only in its exact documented form, such as `Bash(composer test)` or `Bash(npm run lint)`. Claude Code asks before any other form, such as `composer run test`, `npm exec` or a `docker run` with other arguments. Rules for single-purpose tools such as `./vendor/bin/phpunit` end in `:*` and match any arguments. So `./vendor/bin/phpunit --filter testName` runs without a prompt.

To pre-approve another command for yourself, add it to `.claude/settings.local.json`.

## `.claude/settings.local.json`

`.claude/settings.local.json` holds your personal permission overrides, such as machine-specific or experimental permissions. The project's `.gitignore` lists the file, so it stays out of your commits and the team never gets it.

## `.artifacts`

`.artifacts` is the directory where agents and developers write temporary output, such as generated plans, notes and reports. Every generated project's `.gitignore` lists it, so files written there stay out of commits.

## Architecture documentation

Scaffold can also ship architecture documentation: a walkthrough of how the project works, with diagrams an AI agent traces from the source code. It lives in `docs/content/architecture/`, so the documentation site serves it with the project's other pages.

When AI agents are enabled, `init.sh` asks for the **AI architecture docs** diagram format. Pick the format that matches your toolchain:

| Format | Flag | Diagrams |
|---|---|---|
| `mermaid` (default) | `--ai-arch-docs` or `--ai-arch-docs=mermaid` | Fenced Mermaid blocks in the Markdown. GitHub renders them natively in its light and dark themes. The documentation site renders them through its bundled `@docusaurus/theme-mermaid` theme. They need no toolchain. |
| `plantuml` | `--ai-arch-docs=plantuml` | Committed `.puml` sources, rendered to committed light `.svg` files with `plantuml -tsvg docs/content/architecture/*.puml`. |
| `none` | `--ai-arch-docs=none` or `--no-ai-arch-docs` | None. `init.sh` removes the feature. |

`--no-ai` removes the architecture documentation too.

The feature ships the following files:

- `.claude/skills/update-architecture-docs/SKILL.md`: a committed Claude Code skill with the instructions an agent follows to generate and maintain `docs/content/architecture/README.md`
- `docs/content/architecture/README.md`: a starting walkthrough of the template's example code, trimmed to the stacks you selected
- An "Architecture Documentation" section in `AGENTS.md`, which instructs agents to update the documentation after any structural change

An agent regenerates the walkthrough by running the skill. To start a run, ask your agent to "update architecture docs". The agent analyzes the codebase and rewrites `docs/content/architecture/README.md`. The result has a component diagram and a flow diagram for each primary flow from the real entry points. When the documentation and the code disagree, the code wins.

The `plantuml` format needs PlantUML installed. Before rendering, the agent runs `plantuml -version`. When PlantUML is missing, the agent skips rendering and reports that the `.svg` files weren't regenerated. The report includes the install commands: `brew install plantuml` on macOS and `apt-get install plantuml` on Debian or Ubuntu. For every other format, `init.sh` removes the `Bash(plantuml:*)` permission from `.claude/settings.json`.

With `--no-docs`, `init.sh` removes the Docusaurus site and moves the architecture documentation to `docs/architecture/`. It then rewrites every path reference in the generated project to match.
