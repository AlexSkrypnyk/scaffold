# Dotfiles

Scaffold adds `.editorconfig`, `.gitignore` and `.gitattributes` to every generated project, and `.npmrc` to a Node.js project. They set editor formatting, the files Git ignores, the contents of distribution archives and how npm installs dependencies. This page is for developers about to change them.

## `.editorconfig`

`.editorconfig` sets the indentation and formatting rules for each file type. Editors that support the [EditorConfig](https://editorconfig.org/) standard apply those rules, so every supporting editor applies the same indentation and whitespace settings.

The template's [`.editorconfig`](https://github.com/AlexSkrypnyk/scaffold/blob/main/.editorconfig) sets the following defaults for every file:

- LF line endings and UTF-8
- Indentation with 2 spaces
- Trailing whitespace trimmed and a final newline added

`.json`, `.lock` and `.xml` files get 4-space indentation instead.

## `.gitignore`

`.gitignore` lists the paths Git ignores, such as dependencies and build artifacts. `install.sh` removes the template's [`.gitignore`](https://github.com/AlexSkrypnyk/scaffold/blob/main/.gitignore) entries for the features you don't select.

In the generated project, Git ignores the following paths:

- `/.logs`, which holds code coverage reports and test logs
- `/.artifacts/`, which holds temporary output from AI agents and developers
- On a PHP project, `/vendor` and `/.phpunit.cache`, plus `/dist` and `/vendor-bin` when the project builds a PHAR
- On a PHP class library, `/composer.lock`
- On a Node.js project, `/node_modules` and `/yarn.lock`
- On a Node.js library, `/package-lock.json`
- When you select AI agents, `/.claude/settings.local.json` and `/.claude/skills/update-consumer-scaffold/`, both described in [AI integration](./ai-integration.mdx)

A CLI command app, a PHP script and a Node.js app commit their lock files, so CI and every developer install the same dependency versions. A PHP class library leaves `composer.lock` out, and a Node.js library leaves `package-lock.json` out, because the projects that install a library resolve its versions.

When you select AI agents, the file also holds `!/.claude/`. That line lets you commit `.claude/settings.json` even when a global `.gitignore` ignores `.claude`.

To ignore temporary files your operating system creates, use a [global `.gitignore`](https://docs.github.com/en/get-started/getting-started-with-git/ignoring-files#configuring-ignored-files-for-all-repositories-on-your-computer). For the pattern syntax, see the [`gitignore` documentation](https://git-scm.com/docs/gitignore).

## `.gitattributes`

`.gitattributes` sets Git attributes path by path. In a generated project, it marks files and directories `export-ignore`, so `git archive` leaves them out of distribution archives. The template's [`.gitattributes`](https://github.com/AlexSkrypnyk/scaffold/blob/main/.gitattributes) holds its `export-ignore` lines commented out. `install.sh` removes the lines for the features you don't select and uncomments the rest.

In the generated project, `git archive` leaves out the following paths:

- `.editorconfig`, `.gitattributes`, `.gitignore` and `logo.png`
- `docs`, when the project has a `docs` directory
- On a PHP project, `tests`, `phpcs.xml`, `phpstan.neon`, `phpunit.xml` and `rector.php`
- On a Node.js project, `.npmignore` and `.npmrc`

The archive keeps `.github` and `renovate.json`, because an [OpenSSF Scorecard](./ci/audit.mdx) run in its default archive mode reads the repository through it. Without them, that run finds no workflows and no dependency update tool. The shipped `Audit` job sets `file_mode: git`, so it reads the Git checkout instead. The 2 paths add a few kilobytes to a Composer `--prefer-dist` download.

In archive mode, Scorecard also looks in the archive for fuzz tests. When you add property-based or fuzz tests to `tests`, delete the `/tests` line so the archive keeps them.

## `.npmrc`

`.npmrc` holds npm settings for the project. On a Node.js project, it sets `ignore-scripts=true`, so npm skips the install scripts of your dependencies. A compromised package then can't run code when you install it.

The setting also skips the `pre` and `post` scripts around `npm run`, such as a `pretest` script before `npm test`. To run one of those scripts, call it by name, such as `npm run pretest`.

2 more settings shape the tag and the commit that `npm version` creates for a [release](./nodejs/release.mdx). `tag-version-prefix=""` makes the tag the bare version, such as `1.2.3`. `message="Released %s."` sets the commit message.
